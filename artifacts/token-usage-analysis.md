# Django 上下文压缩对照分析


| 指标 | 无压缩 | 压缩 |
|---|---:|---:|
| 总 tokens（输入＋输出，含摘要开销） | 196,888 | 120,717 |
| 压缩次数 | 0 | 7 |
| 模型费用估算 | $0.0101 | $0.0302 |
| 首末动作响应时间戳跨度 | 42 秒 | 82 秒 |
| 输入缓存命中 tokens | 177,792 | 52,992 |
| 输入缓存命中率 | 92.01% | 48.15% |

1. **总 tokens 减少 38.69%。** 摘要请求增加了 39,245 tokens，但后续动作请求不再重复携带完整历史，节省的用量超过摘要开销。
2. **共压缩 7 次。** 每次都缩小了活动上下文，按相同字符粗估口径计算，单次缩减 13.4%–77.5%。
3. **模型费用和运行时间跨度增加。** 费用估算约为基线的 3 倍；模型调用从 18 次增至 27 次，其中 7 次是串行摘要请求，增加了等待和生成开销。时间跨度从 42 秒增至 82 秒，但现有记录无法将全部差值归因于压缩。
4. **输入缓存命中减少。** 命中率从 92.01% 降至 48.15%；历史替换为摘要后，缓存复用减少，未命中输入从 15,443 增至 57,054 tokens。加上额外摘要输出，导致总 tokens 更少但费用更高。
